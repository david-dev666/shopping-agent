# 标题规格证据 v1

2026-10-17。此版本是“同款证据与有限补查”的第一步：先建立可检查的标题证据与确定性约束。尚未实现详情补查、自动追问或任务检查点恢复。

## 数据与边界

每条 `RawOffer` 新增可选的 `match_report`，仅保留逐字段比较、标题原文片段和判断原因；查询由父响应持有，需求 / 商品属性以 `checks` 为唯一对外表示，不再重复序列化完整提取对象。`source=title_rules_v1`，`sku_verified` 与 `price_verified` 始终为 false。

结构化属性包括品牌、品类、部分明确型号、手环/手表代数、版本、NFC 功能、颜色和成色。当前重点覆盖手环代数与版本以及 Y 系列 / RTX 等明确型号；不提取容量、CPU、套装、会员条件、运费或库存。不识别的字段不应被解释为已核对。

品牌沿用共享别名与兼容语境规则；不将“适配某品牌”当作商品品牌。没有 NFC/Pro 文字不等于标准版；Pro 宣传 NFC/蓝牙功能不等于两个版本；显式斜线版本、多个代数或版本则标记待确认。否定词采用有限规则识别，不是完整自然语言理解。

## 四种状态

| 状态 | 页面文案 | 语义 |
|---|---|---|
| compatible | 已识别属性一致 | 仅已提取的标题属性一致，未证明完整 SKU 同款 |
| insufficient | 规格信息不足 | 需求中的属性缺失或缺少可识别的具体型号 / 代数 |
| ambiguous | 混卖或多规格 | 无法把多个代数 / 版本或需求指定的多项属性对应到单一报价 |
| conflict | 规格冲突 | 明确属性不符，或标题声明违反需求明确排除的条件 |

字段级状态区分 consistent、conflict、unknown、ambiguous、not_requested；unknown 不视为一致，未限定的字段仍显示标题提取值。

## 推荐与接口不变量

1. 搜索、样例、Agent 和重排都生成标题证据，报价列表完整保留。
2. 标注使用用户原始需求，模型规范化搜索词不能删除用户指定的版本。
3. conflict / ambiguous 不产生首选；预算、警示、规格优先级与分数单调约束由共享函数执行，主流程、独立排序和样例复用。
4. 可推荐候选中，已识别属性一致优先于信息不足；信息不足只能给待确认建议，不输出 buy 结论。
5. 模型收到完整标题与精简的结构化证据，不截断标题末尾的版本信息。
6. 重排从服务端快照重新计算证据，独立排序入口仍重新核对输入标题；筛选支持 `filters.match_status`，服务端与前端保持一致。
7. 前端首选卡再次检查证据状态；推荐卡、候选、对比表展示原文依据；平台摘要不将混卖 / 冲突候选作为可比报价。

**重排已绑定服务端候选快照。** 查询、样例与 SSE 最终结果附带 `snapshot_id` 和 `snapshot_expires_at`。`/api/refine` 只接受快照 ID、筛选条件和可编辑预算 / 偏好；查询、候选、原始意图与数据来源取自服务端，拒绝额外的 offers / query / intent / data_mode 字段。旧请求格式已移除，前端已同步更新。

快照存储在现有数据库的 `candidate_snapshot` 表，有效期 24 小时；新增快照时清理过期记录，读取时同样检查有效期。失效或不存在返回 404，提示重新查询。缓存命中复用原快照；重排继续引用初始全量快照，放宽筛选能恢复候选，不修改已保存的报价。用户新标记为不相关的候选在重排时排除。样例重排也只使用保存的候选，不重新加载样例文件。

当前沿用本地单用户模型，随机快照 ID 不是多用户身份认证；公开部署前需绑定用户或会话。快照保护的是重排输入，不证明初始采集标题、实际选中 SKU 或价格正确。独立 `/api/rank` 仍是接受显式报价的无状态排序工具，未改为快照协议；页面推荐更新使用 `/api/refine`。

## 验证

- 标题证据阶段后端 276 项测试；该阶段新增 40 项，覆盖代数 / 版本冲突、混卖、NFC 功能与否定、品牌兼容语境、字段缺失、长标题末尾、模型违规首选、重排报告重算、状态筛选及 HTTP 序列化。
- 前端 26 项测试；本轮新增 5 项，覆盖证据转义、缺失状态、首选兜底、汇总和筛选。
- 原 120 条标签开发回归不变；这些测试不是独立保留集，不构成线上同款准确率。
- wheel 冒烟检查包含 `evidence.mjs`，并验证样例响应包含证据。

## 浏览器与真实链路复核

- 样例筛选到 10 条混卖候选并更新：不产生首选购买链接；原因明确指向混卖 / 冲突，平台摘要显示暂无可比报价。
- 手机 320px / 390px 与桌面 1280px 无整页横向溢出；对比弹窗包含两份可展开证据。
- 真实查询“预算300元买小米手环9 NFC版”返回45条候选，三平台各15条；规则状态为6条已识别属性一致、18条冲突、12条混卖、9条信息不足。没有同时满足预算、警示与证据条件的候选，因此未生成首选。

上述状态数量只证明当前规则与链路运行，不是人工核对的正确率，也不能证明采集稳定性或所选 SKU 的价格。

本轮快照与评测工具验证：后端 303 项、前端 26 项通过；覆盖快照持久化、失效、输入替换拒绝、样例 / 实时 / SSE 入口、连续筛选恢复、AI 标签来源、待确认统计与重复候选检查。安装包冒烟包含快照重排。

评测已改为小规模 [Codex AI 辅助评测](../backend/eval/README.md)：20 例真实历史标题与报价，由 Codex 逐例评阅并保留理由。缺失属性、混卖或其他不能确认的条件标 null，不要求人工标注、抽查或凑满 200 组。报告是系统与 AI 弱标签的一致性，不是独立 SKU 或线上准确率。

后续优先级：由 Codex 按真实失败场景小批补例 → 需求澄清 → 限次数 / 时长的关键候选补查 → 持久化检查点与恢复。

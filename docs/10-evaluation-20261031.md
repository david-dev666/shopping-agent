## 完整 Agent 耗时

测量入口为真实 `POST /api/chat`，包含意图解析、采集、匹配、筛选、模型决策和推荐；显式 `data_mode=live`，不使用固定样例或价格缓存。保存查询、模型实际决策引擎、完整响应、节点耗时、端到端耗时和平台结果，记录代码版本、源码哈希及运行环境。首节点 intent 的旧 trace 耗时为 0，因此不把它作为解析耗时；端到端用客户端单调时钟测量。

### 拼多多登录恢复前

四个需求依次重复测量，计划 12 次。在用户要求暂停登录时停止：已完成 9 次，另 1 次在等待 HTTP 响应时被用户暂停。中断请求保留在分母中，但不编造缺失的耗时；剩余 2 次未发起。

- 9 次完成结果均为 live、模型决策引擎为 llm，京东及淘宝各返回 15 条；拼多多均为空。
- 9 次有耗时记录的端到端：中位数 **18.41 秒**，最小 **16.67 秒**，最大 **21.60 秒**。
- 采集节点中位数 **12.18 秒**；决策节点中位数 **5.28 秒**。
- 近邻秩 P95 为 21.60 秒；9 个样本下它等于最大值，只描述本轮样本，不作为稳定尾延迟指标。
- 这组数据不作为三平台完整返回的耗时或登录恢复后的平台成功率。

## 测量工具的停止条件

`scripts/bench_live.py` 默认最多 3 次、每个需求最多 1 轮。收到 403/429、验证码或访问频繁提示、空平台结果、请求失败或用户中断后，不发起下一轮。脚本在完整 HTTP 响应边界检查停止条件，不会强行取消已经提交给浏览器 daemon 的命令，也不代替人工登录或验证。

仅在需要重新核验时手动运行，下面命令最多一次：

```bash
cd backend
PYTHONPATH=. .venv/bin/python scripts/bench_live.py --queries eval/live_queries.txt --max-samples 1 --output /tmp/shopping-live-new-check
```

输出目录必须是新目录，避免覆盖旧记录。测试不会自动访问平台；测量 CLI 仅在显式运行时发出请求。

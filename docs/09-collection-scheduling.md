# 采集调度与取消

更新：2026-10-31。

## 行为

- 所有查询入口的真实采集接入同一个进程内调度器。以平台适配器类型、平台、查询词及凭据作用域合并正在执行的采集；不合并不同预算下的模型决策。
- 共享的是原始候选，每个调用者得到深拷贝，后续打标、反馈和筛选不会互相污染。
- 只有在途任务共享；完成后移除，不把旧价格隐式缓存。直接查询原有的 5 分钟缓存仍独立存在，Agent 查询不因此获得价格缓存。
- 活跃与排队的平台采集任务合计默认最多 16 个，最多 4 个执行线程。同一任务的等待者可以加入已有任务；新任务超额时返回可重试的繁忙错误。全部平台都繁忙时，非流式接口返回 429 和 Retry-After；SSE 返回错误事件。
- 同一次查询的浏览器平台按 PDD → 淘宝 → 京东提交，进入进程内 FIFO 队列，每次只派发一个浏览器任务；等待中的浏览器任务计入容量，但不占执行线程。联盟 API 任务仍可并发，所有任务共用上述线程与容量上限。
- 平台任务的默认截止时间为 45 秒，从提交起计入排队时间。这不是整个 Agent 的总耗时限制。失败平台保留错误，成功平台的结果继续返回；临时排队/截止错误不写入直接查询缓存。
- SSE 断连信号传递到采集等待。一个等待者取消，不停止其他等待者仍需要的任务；最后一个等待者退出后，尚未启动的任务取消，执行中的联盟 API 任务取消在途异步调用；浏览器任务在安全边界协作停止。

## 浏览器的安全边界

浏览器导航与提取仍共用完整操作锁。排队及轮询期间检查取消和截止时间。已经提交的 daemon 命令不会因为调用者停止等待就被视为已经结束：资源保留至命令完成，然后在安全边界停止后续操作。

平台优先顺序保证本次新提交的较快平台先执行，京东单独超时时保留其他平台已取得的结果。不会抢占其他查询已在使用的标签页；若共享浏览器此前已被占用，后续平台仍可能在排队中超时。

HTTP 传输超时或断开不能证明浏览器动作已停止。客户端将浏览器标记为状态未知，拒绝后续采集；需人工确认 daemon 已空闲，再重启应用恢复。模型在途调用的强制取消尚未实现。

## 配置与部署

```dotenv
COLLECTION_WORKERS=4
COLLECTION_CAPACITY=16
COLLECTION_TIMEOUT_SECONDS=45
```

`/api/status` 增加提交、合并、拒绝、当前未完成任务及容量计数。

调度器、浏览器锁和直接查询缓存均是进程内状态。使用共享浏览器时只运行一个应用 worker；此实现不提供跨进程/多实例资源协调，也不提供持久化任务恢复或多用户浏览器会话隔离。

## 验证

```bash
cd backend
uv run ruff check app tests scripts/bench_collection.py
uv run pytest -q
PYTHONPATH=. uv run python scripts/bench_collection.py
```

离线模拟：20 个并发相同查询，每个查询三个平台。不合并时 60 次适配器调用，合并后 3 次、57 次加入已有任务。这是受控适配器的请求合并验证，不是线上平台吞吐或 P95 延迟。

测试覆盖跨事件循环共享、候选深拷贝、凭据隔离、单等待者取消、全部等待者退出、容量拒绝、排队截止、浏览器命令未结束时保留资源、传输状态未知时拒绝复用、部分平台失败和 429 响应。浏览器队列回归覆盖单线程/多线程下的平台顺序、慢京东不丢失前两个平台的结果、等待任务不占用 API 工作线程、队列取消/过期不进入适配器及失败后继续派发。

本轮验收：后端 330 项离线测试通过，ruff 检查通过。未执行真实平台压力测试或改写简历性能指标。

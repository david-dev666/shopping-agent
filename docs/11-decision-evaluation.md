# 决策约束评测与三平台耗时

## 决策约束

固定18组自建候选场景：预算、型号冲突、混卖、配件、二手、无合适候选六类，各三个预算条件。输入为构造数据，标签在运行前固定，15组存在合适候选、3组必须不推荐。复用实际打标、筛选、决策、确定性约束和推荐链路；不调用平台采集或意图解析，不宣称真实SKU或通用推荐准确率。

| 模式 | 完成 | 有合适候选时正确选择 | 无合适候选时不推荐 | 错误/超预算首选 |
|---|---:|---:|---:|---:|
| 规则降级 | 18/18 | 15/15 | 3/3 | 0/0 |
| 配置模型真实调用 | 18/18 | 15/15 | 3/3 | 0/0 |
| 故意把错误候选排首位的输出注入 | 18/18 | 15/15 | 3/3 | 0/0 |

三种模式共54次执行，不等于54组独立样本。首选覆盖率15/18（83.33%），已选首选合适率15/15；有合适候选时选择成功率15/15，同时单列无合适候选时的不推荐。执行异常不计正确拒绝。模型模式18次均实际使用llm；注入模式单独统计，不混为真实模型效果。

输入及标签为 `backend/eval/decision_cases.jsonl`，哈希见同名manifest。完整响应及轨迹见 `backend/eval/reports/decision-and-latency-20261101/decision-*.json`。

复现（rules/adversarial不访问平台或模型，llm会调用已配置模型）：

```bash
cd backend
DATABASE_URL=sqlite:////tmp/shopping-decisions.db PYTHONPATH=. .venv/bin/python scripts/eval_decisions.py --engine rules --output /tmp/decisions-new.json
```

将engine改为llm或adversarial并使用新的输出文件，可分别复现另外两种模式。

## 三平台完整查询耗时

统计3个不同需求各一次完整查询，显式live、非缓存、非样例，三平台每次各15条，共45条。包含意图解析、采集、匹配、筛选、模型决策、推荐及HTTP返回。

| 需求 | 京东/淘宝/拼多多 | 耗时 |
|---|---|---:|
| 预算300元买小米手环9 NFC版 | 15/15/15 | 14.46s |
| 预算300元买华为手环9 | 15/15/15 | 12.15s |
| 预算300元买荣耀手环9 | 15/15/15 | 12.95s |

算术平均13.18504秒，简历取13.2秒；精确范围12.14847–14.45989秒。这里只统计三平台完整返回样本，不用于估计成功率、可用性或稳定P95，不宣称各需求完成了重复测量。原始完整响应与样本清单见报告目录complete-latency。

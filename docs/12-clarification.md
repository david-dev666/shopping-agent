# 规格澄清与候选快照续接

2026-11-01。当前智能选购要求模型可用；不再在模型缺失或失败时生成规则推荐。最新评测见 [Agent 评测](13-agent-evaluation.md)。当前支持手环 / 手表的代数、版本澄清。模型负责需求理解与排序；是否追问、选项校验、预算与规格约束由代码执行。

## 行为

1. 采集、标题核对与用户筛选后，检查可用候选中的规格差异。
2. 需求已有明确代数 / 版本，不追问该属性。无警示、预算内且证据不冲突的候选至少包含两种明确值，才询问缺失属性；不从冲突、混卖或仅缺少标题属性的候选生成选项。需求须有可识别品牌和手环 / 手表品类。
3. 有问题时，LangGraph 的 `review` 条件边结束本轮，返回 `status=awaiting_clarification`，不调用排序模型、不生成首选。前端展示选择项，包含“不限”。
4. 用户提交后，服务端从原候选重新核验问题与选项。只接受当前支持的问题，不允许覆盖原需求、标题、报价或指定已有明确值的属性。
5. 基于确认后的需求重新核对全部标题证据，再运行 `filters → review → decide → recommend`。如仍有未回答的问题，继续等待；不重新采集。全部满足后进入模型决策与确定性约束链路（模型必需）。

不要求缺少预算的用户必须填写预算；当前未支持的容量、CPU、套装等属性不自动追问。若用户选择的组合没有合适报价，沿用保守的不推荐结果，不通过补查或放宽约束制造候选。

## 快照与接口

原有查询、SSE 和重排入口保持不变。`/api/refine` 新增可选 `answers`：

```json
{
  "snapshot_id": "服务端返回的32位快照ID",
  "answers": {"version": "NFC版"},
  "filters": {},
  "constraints": {"budget": 300, "preference": "价格优先"}
}
```

`answers` 只允许 `generation`、`version`，值必须来自服务端当前可提供的选项。选项从不可变全量快照按有效预算、反馈与规格证据重算；临时筛选不能改变保存的候选。错误答案返回 422，过期快照返回 404。

确认后生成新快照 ID，只更新确认条件与有效意图，保留原始全量候选、原需求、来源和原过期时间；父快照不修改。新快照保存回答和已编辑预算 / 偏好，后续请求与数据库连接重建后仍可继续。筛选不改变已确认规格，放宽筛选可恢复候选。原始标题与价格不被客户端或模型替换。派生快照不延长报价有效期。

响应包含 `clarifications`、`effective_query`、`clarification_questions`、`status`。已确认规格的重排额外返回 `candidate_offers`，用于同步前端全量候选的标题证据，避免推荐和列表显示不同核对状态。固定样例保持原交互，不模拟真实追问。

此处是应用层的候选快照续接；没有接入 LangGraph checkpointer，不支持从崩溃的在途节点自动恢复。单用户本地应用边界保持不变。

## 轨迹修复

- `steps_json` 改为 Text，去除序列化后的字符串截断，避免长 JSON 无法解析；迁移版本为 `a4f91b2c730e`。
- 非流式全量和重排入口发生异常时，保存已完成节点与 `failed` 记录；SSE 沿用失败 / 取消轨迹保存。
- `review` 记录确认条件及生效需求；SSE 根据实际条件边发出后续进度，等待回答时不发送未执行的决策 / 推荐进度。

## 验收与限制

使用构造候选执行离线验收，覆盖明确需求直达决策、缺失代数 / 版本追问、不限、预算 / 筛选 / 警示限制、错误答案、父快照不变、过期拒绝、数据库连接重建、回答后不重新采集、前端证据同步、长 JSON 与同步失败轨迹。浏览器另用固定六条候选检查追问表单、NFC 回答续接及移动端布局；不是电商实时采集测试。

当前验证与开发回归结果统一记录在 [Agent 评测](13-agent-evaluation.md)。历史 13.2 秒数据属于改动前的三次完整查询，本轮未重新测量。
